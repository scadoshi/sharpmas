landed the same day there; its 2026-09-13 entry has the bug that started it.

`Totals` in `Domain/Solution/` folds in one `Solved` at a time. Two running
fields rather than two lists, `Days` public for the caller to gate on, and
`ParseMean` and `SolveMean` returning `TimeSpan?` so the no-days case has one
home instead of one per division. The rustmas draft divided a `Duration` by a
list length and panicked on `-y 2019`. C# would have thrown `OverflowException`
on the same line, so the fix carried over unchanged.

`Outcome.SolveTime` is a `TimeSpan?`, null for a stub, a failure, and day 25's
second star. It replaces a predicate called `IsOkAndUnwritten` that returned
true when the answer was *not* unwritten.

`Part.Word` gives `one` and `two` for the slowest-part line. Rust used a
`Display` impl; C# needs the property because `Part.One.ToString()` already
returns `One`, which reads fine and is wrong.

The gate is `if (totals.Days > 1)` in `SolveRun`, not in `Totals`. `ToString`
renders whatever it holds and the caller decides when that is worth printing,
since deciding when to print is an output question.

Six tests, asserting through `Environment.NewLine`, because `AppendLine` is
platform dependent where rustmas's `\n` is not. 127 pass.

## The comment pass

42 comment lines cut. Same rule as rustmas, already in `rules/doc_comments.md`:
a second sentence earns its place only for a trap, a rejected alternative, a
decision that looks like a mistake, or a cross-reference.

C# makes this worse than Rust does. `/// <remarks>` and `/// </remarks>` are two
lines of pure tag per block, so across 86 blocks that is 172 lines carrying no
words. A five-line block is three lines of prose. Worth knowing before reading a
raw comment count as if it measured verbosity.

Biggest cut was the cache tree in `Store.cs`, thirteen lines reproducing
`architecture.md`. `Outcome`'s class remark opened "The four properties have
three different sources", which adding `SolveTime` would have made wrong on
arrival, so that went too.
